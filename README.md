# 📊 E-Commerce Marketplace SQL Analysis (SQL Server)

## 📌 Project Overview

This project explores and analyzes an e-commerce marketplace dataset using SQL Server.
The goal is to extract meaningful business insights related to **payments, sellers, customers, and reviews** to support data-driven decision-making.

The analysis focuses on understanding:

* Revenue and payment behavior
* Seller performance and pricing patterns
* Customer geographic distribution
* Review trends and customer satisfaction
---
## Dataset Source

The dataset used in this project is publicly available on Kaggle:

👉 https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce

---
## 🎯 Business Objectives

The project aims to answer key business questions such as:

* What is the total revenue generated by the platform?
* Which payment methods are most used and most profitable?
* How do installment plans affect purchasing behavior?
* Which sellers generate the most revenue?
* Which sellers are associated with poor customer experiences?
* Where are the majority of customers located?
* How are review scores distributed?

---

## 🗂️ Dataset

The dataset is based on a Brazilian e-commerce marketplace and includes the following tables:

* `customers`
* `order_items`
* `payments`
* `reviews`
* `sellers`

> ⚠️ Note: Some tables (`orders`, `products`) could not be successfully imported due to technical issues (see Challenges section).

## 🧠 Methodology

### 1. Data Exploration

Initial queries were used to explore each table:

```sql
SELECT * FROM customers;
SELECT * FROM sellers;
SELECT * FROM reviews;
SELECT * FROM order_items;
SELECT * FROM payments;
```

---

### 2. Payment Analysis

Analyzed revenue, payment methods, and installment behavior.

Key techniques:

* `SUM()` for total revenue
* `COUNT()` for transaction volume
* `AVG()` for average payment
* Subqueries for percentage calculations

Example:

```sql
SELECT 
    payment_type,
    SUM(payment_value) AS total_revenue
FROM payments
GROUP BY payment_type
ORDER BY total_revenue DESC;
```

---

### 3. Seller Performance Analysis

Evaluated seller contribution and pricing behavior.

Key metrics:

* Total revenue per seller
* Average item price
* Freight cost analysis
* Identification of high-performing sellers

Example:

```sql
SELECT
    seller_id,
    SUM(price) AS total_revenue,
    AVG(price) AS avg_price
FROM order_items
GROUP BY seller_id
ORDER BY total_revenue DESC;
```

---

### 4. Customer Analysis

Analyzed geographic distribution of customers.

Example:

```sql
SELECT
    customer_state,
    COUNT(*) AS number_of_customers
FROM customers
GROUP BY customer_state
ORDER BY number_of_customers DESC;
```

---

### 5. Review Analysis

Explored customer satisfaction and review distribution.

Example:

```sql
SELECT 
    review_score,
    COUNT(*) AS reviews_count
FROM reviews
GROUP BY review_score
ORDER BY review_score;
```

---

### 6. Multi-Table Analysis (JOINs)

Connected reviews with sellers using `order_items` to identify sellers associated with poor customer experiences.

Example:

```sql
SELECT
    oi.seller_id,
    COUNT(CASE WHEN r.review_score <= 2 THEN 1 END) AS bad_reviews,
    COUNT(*) AS total_orders,
    COUNT(CASE WHEN r.review_score <= 2 THEN 1 END) * 100.0 / COUNT(*) AS bad_review_percentage
FROM reviews r
JOIN order_items oi
    ON r.order_id = oi.order_id
GROUP BY oi.seller_id
ORDER BY bad_review_percentage DESC;
```

## 🔍 Key Insights

* **Credit cards dominate** as the primary payment method.
* Customers frequently use **installment payments**, indicating reliance on financing.
* Some sellers generate high revenue through **volume**, while others rely on **high-value products**.
* Sellers with high **average freight costs** may negatively impact customer satisfaction.
* A subset of sellers is associated with a **higher percentage of low review scores**.
* Customer distribution is concentrated in a few key states.

## ⚠️ Challenges Encountered

### 1. Data Import Issues

* The `orders` and `products` tables failed to load into SQL Server.
* Errors included:

  * File path issues during `BULK INSERT`
  * Data format inconsistencies

### 2. Impact of Missing Tables

Because of missing tables:

* Could not fully connect **customers → orders → payments**
* Could not perform **product-level analysis**
* Limited ability to analyze full order lifecycle

### 3. Workaround Strategy

To overcome this:

* Focused analysis on available tables
* Used `order_items` as a bridge between sellers and reviews
* Clearly defined project limitations

* No direct linkage between customers and payments
